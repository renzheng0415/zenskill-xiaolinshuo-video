# 讲解画面审片要点

> 根据 howoneai/xiaolin-explainer-packaging 的 `references/style-bible.md` 改写（MIT，Copyright (c) 2026 howoneai，见根目录 NOTICE.md）。
> **铁律优先**。本文件只用于样片和逐章审片时的人眼检查，不修改编译规则，也不改配色体系（仍是 navy/teal，不用粉色）。

对方从 5 期原片里归纳出一些画面习惯。合进来的是「讲解画面不要像 PPT」这一层，不是对方的引擎默认值。

## 能在本引擎里执行的

1. **主体要大**。图表、大数字或关键词，宽度尽量占到画面六成以上，或者被画面边缘裁切。不要小小一个块居中，四周大片空。
2. **当前项最亮**。正在讲的柱子、词条、对比项要醒目，其余压暗。引擎里用 `h` 标当前项、`p` 标已讲项，bars 用单根柱子颜色标主角（见风格规则 R-M4）。
3. **一帧最多两个标签**。英文/外文小字只放在标题或术语下方，不要每张卡都挂一排装饰标签。
4. **不要挡住字幕、人物脸、台标区域**。字幕大约在屏幕下方（底边约 96px，中心约 955px）；圆形小窗底边不要低于 940 像素；叠字和来源行避开 y 905–960。
5. **镜头别停在全景不动**。有面板或卡片墙意味的场景，跟着手势或新焦点推近；没有新焦点就不要无意义地来回推。手势镜头仍按铁律：推镜起点放在手势起点，`push.dur: 0.6`。
6. **不要一句一页**。一个图形场景跨 2–8 句，期间逐项出现、高亮、划掉。这一点和风格规则里「人物段 2.5–6 秒、B-roll 成段出现」一致。
7. **开场钩子、观点句、设问和结尾优先全屏出镜**，不要整片盖满图表。
8. **转场默认硬切**。动画转场只放在进出实拍段、章节切换，不要每个切点都甩镜。

## 本引擎做不到、不要硬凑的

| 对方规则 | 现状 | 怎么处理 |
|---|---|---|
| 每 2–3 个深色场景插 1 个白纸场景 | 本引擎图表是深色玻璃卡，已决定不改成白卡 | 用「人物 / 深色卡 / 实拍」交替换气；不要假装已经有白纸版式 |
| 白纸整屏配右下圆形小窗，公式配左侧竖条小窗 | 只有圆形 pip，且铁律要求 pip ≤ 10% 镜头 | 按铁律少用小窗；竖条小窗记到 ChatCut/手工备注 |
| 卡片墙镜头跟随当前卡、其余虚化 | 本引擎没有 `wall` 跟拍 | 用连续 card，或写进备注 |
| 原文页荧光笔、网页截图聚光 | 没有 `docpage` / `webshot` 组件 | 先把官方页截下来当 card/broll 底，再用叠字标出原句；精细荧光笔交给备注或 ChatCut |
| 片名卡粉色胶片孔 | 铁律不用粉色 | 不做 |
| 成片必须带「AI 生成」标注 | 铁律默认不加 AI 标，除非用户要求 | 不做 |
| 音乐说话时低 12–16 dB、真峰值 -1.5 dBTP | 铁律：音乐床约 -18 dB，成片 -16 LUFS / ≤ -1 dBTP | 不改铁律里的声音标准 |

## 样片和逐章时逐项看

每一组审片抽帧，问这 8 句：

1. 主体够大，还是像一张小 PPT？
2. 眼睛会先落到正在讲的那一项吗？
3. 这一帧是不是标签太多？
4. 字幕、脸、小窗有没有互相挡住？
5. 屏幕上的数字、单位是不是跟口播同一个写法？来源行在不在？
6. 这一镜有没有本期专属的照片、道具、Logo 或官方截图？（只有骨架和数字就不合格）
7. 硬切和弱口型是不是落在 broll/card/chapter 上？
8. 素材许可登记了吗？CC BY / BY-SA 的署名在不在画面或发布文案里？
